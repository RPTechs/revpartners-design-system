badge 3. Visitor Identification

Goal: HubSpot knows the logged-in user by email, greets by first name, and skips the “who are you?” capture. Needs Professional or Enterprise.

Flow

1) Frontend: set loadImmediately: false. 2) Backend: create token with the user’s email (and name if you have it). 3) Frontend: set identificationEmail + identificationToken. 4) Call widget.load().

HubSpot / RevPartners

API access

Provide a private app (or OAuth) with scope conversations.visitor_identification.tokens.create. Never put that secret in browser code.

SETWorks developer — backend

Create the token on your server

Call HubSpot from your backend after the user is authenticated. Official example request:

developers.hubspot.com · Visitor Identification guide 
curl --request POST \
  --url 'https://api.hubapi.com/visitor-identification/v3/tokens/create' \
--data '{
  "email": "gob@bluth.com",
  "firstName": "Gob",
  "lastName": "Bluth"
}'

Authenticate with your private app token / OAuth access token (Bearer). Response includes a token string. Return that token to your frontend over your own authenticated API — do not expose HubSpot credentials.

API note

HubSpot’s current create-token schema also lists hsCustomerAgentContext as required on newer API versions. Check the live create endpoint before you ship. Do not invent fields — use the reference.

timer 4. Token Expiry + Refresh

SETWorks developer

Tokens last 12 hours

From HubSpot: set email + token on hsConversationsSettings every page load for an authenticated visitor. That context does not carry over by itself if you stop setting it.

Tokens expire after 12 hours. You may cache the token and skip a HubSpot call on every load, but refresh it at least every 12 hours.

  • On login / session start: fetch a fresh token.
  • On full page load: reuse cached token if still valid; else fetch again.
  • On logout: clear chat state (see below).

route 5. SPA Notes

SETWorks developer

Track route changes

The tracking code records one page view on first load. On client-side navigation, update the path and track again:

Tracking code API · SPA page views 
<!-- Set up the path for the initial page view -->
<script>
  var _hsq = window._hsq = window._hsq || [];
  _hsq.push(['setPath', '/home']);
</script>

<!-- Load the HubSpot tracking code -->
<!-- Start of HubSpot Embed Code -->
  <script type="text/javascript" id="hs-script-loader" async defer src="//js.hs-scripts.com/48197330.js"></script>
<!-- End of HubSpot Embed Code -->

<!-- Tracking subsequent page views -->
<script>
  var _hsq = window._hsq = window._hsq || [];
  _hsq.push(['setPath', '/about-us']);
  _hsq.push(['trackPageView']);
</script>
SETWorks developer

Refresh the chat widget on route change

URL targeting uses the current page URL. After you change the route, refresh the widget:

Chat Widget SDK · widget.refresh 
window.HubSpotConversations.widget.refresh();

/* ... */

// Force the widget to open to a specific chat flow
window.HubSpotConversations.widget.refresh({ openToNewThread: true });

Throttled to one call per second. If the route has no matching chatflow and the user is not in an active chat, refresh can remove the widget.
