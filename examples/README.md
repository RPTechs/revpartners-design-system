# Example deliverables

These are **vibe specimens**, not templates.

Study them for proportion, type, padding, 8px boxes, 2px borders, button pad (`15px 40px`, Inter 700, 16px), green chrome, nested ask/stop/info, and how a real client doc feels. Then **design the layout this content needs**. Two scoping docs should not look identical just because they’re both scoping.

**Do not** duplicate a file and swap the copy. **Do not** dump prose into `docs/01-branded.html` or `docs/02-working.html`. Those are empty letterhead. Claude’s failure mode is paste-into-working.html and call it a deliverable.

Steal the parts. Invent the composition. Use the component recipes in `DESIGN.md` (cards, callouts, tables, diagrams, lists, BLUF). Header/footer chrome can stay family — the middle is yours.

| File | What to steal from it |
|---|---|
| `feasibility-jesus-image-stripe-checkout.html` | Short BLUF, one flow, tight estimate table. Quiet. |
| `process-channel-engine-dedupe.html` | Decision tree. Stems that actually touch cards. |
| `spec-mentavi-journey-event.html` | Long spec: TOC, nested ask/stop/info, lists that stop at orange. |
| `one-pager-forecast-purchase-orders.html` | Compact “how the build works.” Dense without looking dumped. |
| `guide-chat-visitor-identification.html` | Step-by-step with code that still looks like us. |
| `guide-tech-scorecard-epic-metrics.html` | Operating guide / scorecard / RACI. |

Shared files live in `assets/` (favicon, prism, spec figures).

Not in this folder on purpose: marketing landings (RPM-style dark hero), portal indexes, and anything with an orbit diagram pretending to be a brief.
