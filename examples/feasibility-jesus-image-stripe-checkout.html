Application Fee Student Association Feasibility

The question

Can we record each application fee in HubSpot and associate it with the correct student and Application — even when a parent, spouse, or sponsor pays using their own email at checkout?

Answer

Yes, this is feasible. We can use Stripe-hosted checkout pages (Stripe Payment Links) plus a small automation in your HubSpot account so every fee payment appears on the right Application and student record — and the same student/program details are written back onto the Stripe payment for reconciliation.

The problem today

Why payments are hard to match

Applicants complete their application in HubSpot, then pay an application fee through a shared payment link. Often the person who pays is not the student — a parent, spouse, or sponsor may use their own email at checkout.

HubSpot correctly records the payment, but it associates the payment with whoever entered their email at checkout. Your team cannot reliably see which student the fee was for without manual cleanup.

Recommended approach

How it will work

  1. We set up one Stripe Payment Link per class type (typically three links), each with the correct application fee amount.
  2. When an application reaches the Application fee stage, your portal shows a pay link unique to that application. The portal selects the Stripe link for that class type and adds a tracking ID for the Application.
    https://buy.stripe.com/CLASS_A_LINK?client_reference_id=987654321

    Class type is set by which base link is used (JS_IN_PERSON, JS_ONLINE, HOB_IN_PERSON, etc.). The tracking ID is your HubSpot Application record ID.
  3. The student shares the link. The payer completes Stripe checkout using their own email — no change for families.
  4. When payment succeeds, Stripe notifies a HubSpot serverless function in your account.
  5. That function looks up the Application, creates or updates the HubSpot Payment (associations + payer), marks the fee paid, and writes applicant name, applicant email, program/class, and school year onto the Stripe payment as metadata so finance can reconcile in Stripe as well as HubSpot.

This replaces today’s HubSpot payment-link checkout with Stripe Payment Links, and adds the missing step so the payment follows the application — not only the payer’s email.

Checkout experience

Stripe Payment Links

Stripe Payment Links are hosted checkout pages — the same kind of secure, card-on-file experience families expect. Setup is straightforward: create a product and price for each class fee, then generate a link. Branding (logo, colors, description) is available within Stripe’s standard options.

We do not need to build a custom payment form or handle card data. Stripe remains the payment processor; HubSpot remains your system of record for applications and payments.

Tracking details

What the URL carries — and what we write after payment

ItemEffect
Application tracking ID on the linkTells our automation which Application (and student) the payment is for. Does not change the charge amount.
Class type / fee amountDetermined by which payment link the portal shows (based on the Application). Not a separate URL parameter.
Applicant name, email, program, school yearAlready on the Application in HubSpot. After payment, automation copies these onto the HubSpot Payment and onto Stripe payment metadata. They are not typed again at checkout, and they are not passed as free-form URL parameters.
Extra questions at checkoutOptional. Stripe Payment Links can show up to three buyer-filled custom fields if you want additional info from the payer. That is separate from the applicant/program metadata above.
Reliability

Duplicate payments and payers

Duplicates: Stripe may send the same payment notification more than once. Our automation checks whether a payment was already recorded before creating a new one, so you will not see duplicate Payment records.

Payers: When someone other than the student pays, we can create or update a Contact for the payer and link that person to the payment, while still associating the payment with the correct student and Application.
